# GBR Paints Pro - وثيقة البنية البرمجية والنظام (System Architecture)

مرحباً بك في دليل البنية البرمجية والتصميم المعماري الخاص بنظام **GBR Paints Pro** لإدارة مصانع الدهانات والإنتاج الكيميائي والمختبرات الذكية. توفر هذه الوثيقة دليلاً هندسياً شاملاً يوضح الهيكل المعماري للنظام، والكيانات الرئيسية، ودورات حياتها، بالإضافة إلى تفاصيل تدفق البيانات والعمليات.

---

## 1. فلسفة النظام (System Philosophy)
تم تصميم نظام **GBR Paints Pro** كحل تقني متكامل وقابل للعمل دون إنترنت (**Offline-First**) موجه لمصانع الدهانات والصناعات الكيميائية. يرتكز النظام على الأسس التالية:
* **الأداء العالي والاستجابة الآنية**: الاعتماد على قاعدة بيانات Room المحلية كمرجع وحيد للحقيقة (Single Source of Truth) على مستوى واجهة المستخدم.
* **سلامة البيانات الكيميائية والإنتاجية**: يطبق النظام قواعد صارمة للتحقق من نسب التركيبات ومطابقة مواصفات الجودة قبل الاعتماد أو البدء في الإنتاج.
* **المزامنة والنسخ الاحتياطي الذكي**: دعم التصدير والاستيراد المخصص والمتقدم (JSON/ZIP) مع إمكانية المزامنة السحابية مع Firestore لضمان استمرارية الأعمال وحماية البيانات الحساسة من الفقدان.

---

## 2. الهيكل المعماري (Architectural Structure)
يتبع المشروع نمط التصميم المعماري **Clean Architecture** المدمج مع **MVVM (Model-View-ViewModel)** لضمان فصل الاهتمامات وسهولة الصيانة:

```
┌────────────────────────────────────────────────────────┐
│                      Presentation                      │
│     (Jetpack Compose UI Screens, GbrViewModel, etc.)   │
└───────────────────────────┬────────────────────────────┘
                            │ (Reactive flows / StateFlow)
                            ▼
┌────────────────────────────────────────────────────────┐
│                      Domain/Data                       │
│      (GbrRepository, SyncManager, BackupManager)       │
└───────────────────────────┬────────────────────────────┘
                            │ (Local SQL / Remote REST/Firestore)
                            ▼
┌───────────────────────────┴────────────────────────────┐
│                       Data Storage                     │
│    (SQLite/Room DB, SharedPrefs, GbrFileManager)       │
└────────────────────────────────────────────────────────┘
```

### أ) طبقة العرض (Presentation Layer)
* **Jetpack Compose UI**: واجهات تفاعلية بالكامل، تدعم اللغتين العربية والإنجليزية وتتكيف مع مختلف الشاشات والأجهزة اللوحية (Tablet adaptive).
* **GbrViewModel**: يمثل محرك التحكم الرئيسي، حيث يدير الحالة الإجمالية للتطبيق عبر `MutableStateFlow` ويقوم بتوجيه طلبات الواجهة إلى المستودع (Repository).

### ب) طبقة البيانات والعمليات (Data & Domain Layer)
* **GbrRepository**: الوسيط الديناميكي بين واجهة البرمجة وقاعدة البيانات المحلية.
* **SyncManager**: يدير مزامنة الجداول تلقائياً والتعامل مع حالات انقطاع الشبكة وإصلاح مخططات قاعدة البيانات المعطوبة.
* **BackupManager**: المسؤول عن توليد حزم النسخ الاحتياطي بصيغتي (JSON/ZIP) ودعم عمليات الدمج الذكي (Smart Merge) أو الكتابة الفوقية الكاملة للبيانات.

### ج) طبقة التخزين (Data Storage)
* **Room Database (SQLite)**: تخزن كافة البيانات الهيكلية للتركيبات، والمواد الخام، وأوامر الإنتاج، وجلسات المختبر، والمرفقات، والتنبيهات.
* **SharedPreferences**: تخزن الإعدادات البسيطة مثل العبوات المخصصة وخيارات التصدير واللغة المفضلة.
* **GbrFileManager**: مسؤول عن حفظ وضغط ملفات الصور والملفات المرفقة (Attachments) بجلسات المختبر والتحقق من سلامتها.

## 3. الكيانات الرئيسية (Key Entities) & العلاقات
يحتوي النظام على كيانات رئيسية مترابطة بالشكل التالي:

```
┌──────────────┐          ┌──────────────┐          ┌─────────────────┐
│ Raw Material ├─────────►│ Formulation  ├─────────►│ Revision/Version│
└──────────────┘          └──────┬───────┘          └─────────────────┘
                                 │
                                 ▼
                          ┌──────────────┐          ┌─────────────────┐
                          │  Prod Order  ├─────────►│  Quality Test   │
                          └──────┬───────┘          └─────────────────┘
                                 │
                                 ▼
                          ┌──────────────┐          ┌─────────────────┐
                          │ Lab Session  ├─────────►│ Lab Attachment  │
                          └──────────────┘          └─────────────────┘
```

1. **المادة الخام (Raw Material)**: اللبنة الأساسية لأي منتج. تدخل في تركيب المنتجات ولها تكلفة وسعة تتبع وحالة فحص جودة.
2. **التركيبة الكيميائية (Formulation)**: تحدد مكونات ونسب المواد الخام، ولها كود فريد وإصدار مفصل وحالة اعتماد للإنتاج.
3. **مراجعة التركيبة (Formulation Revision)**: سجل تاريخي للتعديلات يوضح التغيير في المكونات أو النسب أو المعايير الفيزيائية.
4. **أمر الإنتاج (Production Order)**: يمثل عملية تشغيل وتعبئة باتش إنتاجي حقيقي بالاعتماد على تركيبة معتمدة، ويقوم بحساب الانحرافات والأوزان والتعبئة الفعلية.
5. **جلسة المختبر (Laboratory Session)**: مخصصة لفحص واختبار جودة الدفعات المنتجة، وتضم اختبارات اللزوجة، الكثافة، الصلابة، والمطابقة الكلية.
6. **مرفقات المختبر (Laboratory Attachment)**: الصور والمستندات الملتقطة بالكاميرا أو المرفقة من الهاتف لتوثيق جودة الباتش أو الانحرافات البصرية.
7. **التنبيهات التشغيلية (Operational Alerts)**: إشعارات وتنبيهات برمجية ذكية ترتبط بآلات معينة أو خطوات إنتاجية أو شذوذ معايير الجودة للتحذير الفوري.

## 4. دورة حياة الكيانات (Entity Lifecycles)

### أ) التركيبة الكيميائية (Formulation)
```
[ مسودة (Draft) ] ──► [ قيد التطوير (In Dev) ] ──► [ معتمدة للإنتاج (Approved) ] ──► [ مؤرشفة (Archived) ]
```
* تبدأ التركيبة كـ **مسودة (Draft)** حتى يكتمل إدخال نسب المكونات لتصبح 100%.
* تنتقل إلى **قيد التطوير (In Development)** لإجراء الفحوصات التجريبية الأولى.
* عند نجاح الفحوصات ومطابقة المواصفات، يتم ترقيتها إلى **معتمدة للإنتاج (Approved for Production)**؛ ولا يمكن استخدام أي تركيبة في تصنيع أمر إنتاج إلا إذا كانت معتمدة.
* في حال تحديث التركيبة أو استبدالها، يتم نقلها إلى **مؤرشفة (Archived)** لمنع استخدامها مجدداً مع الحفاظ على سجلاتها التاريخية.

### ب) أمر الإنتاج (Production Order)
```
[ مخطط (Planned) ] ──► [ قيد التصنيع (In Progress) ] ──► [ مكتمل (Completed) ] ──► [ ملغى (Cancelled) ]
```
* **مخطط (Planned)**: يتم حجز المكونات وتجهيز حاويات التعبئة.
* **قيد التصنيع (In Progress)**: يتم سحب المواد من المخزن وتسجيل الأوزان المدخلة خطوة بخطوة.
* **مكتمل (Completed)**: بعد تعبئة الباتش وتسجيل الانحراف الإجمالي للوزن والعبوات المنتجة.
* **ملغى (Cancelled)**: في حال وجود شذوذ كيميائي أو قرار فني بوقف التشغيل.

## 5. قواعد الحذف والأرشفة (Deletion & Archival Rules)
لحماية البيانات التشغيلية ومنع حدوث مرجعيات فارغة (Broken Foreign Keys):
* **المواد الخام**: لا يمكن حذف أي مادة خام تدخل في تركيبة مسجلة بالنظام؛ يجب تعديل التركيبة أولاً أو أرشفة التركيبة قبل حذف المادة.
* **التركيبات**: عند محاولة حذف تركيبة معتمدة تم استخدامها سابقاً في أمر إنتاج مكتمل، يقوم النظام تلقائياً بـ **أرشفتها** بدلاً من الحذف الفعلي للحفاظ على سجلات الإنتاج.
* **أوامر الإنتاج وجلسات المختبر**: ترتبط جلسات المختبر بأوامر الإنتاج. لا يمكن حذف أمر إنتاج يملك جلسة فحص جودة معتمدة إلا بعد تأكيد مشرف الجودة وحذف الجلسة أولاً أو نقلها للمرشيف التاريخي للباتشات المرفوضة.
